# Noted it

Checklist-driven clinical note scaffolding for psychologists. You tick options;
the app composes them into prose you can paste into your practice system.

> **The output is a scaffold, not a finished note.** Everything it produces must
> be proofread and edited. The clinical record remains the practitioner's
> responsibility.

## What it does

Four document types, generated from the *Noted it Manual*:

| Document | Sections | Items |
| --- | --- | --- |
| Initial Clinical Note | 8 | 57 |
| Clinical Note | 10 | 42 |
| Clinical Progress Letter | 12 | 40 |
| Cognitive Assessment Letter | 10 | 35 |

Plus ten psychometric instruments with automatic band interpretation:
DASS-21, BDI-II, BAI, K10, WHOQoL-BREF, DSM-V CCSM and DIAMOND (adult);
BYI, CBCL and DIAMOND-KID (child/adolescent).

Enter a raw score and the app reports the published band — e.g. a DASS-21
depression score of 6 yields *"Client's depression score was 6 and in the mild
range."*

## Design constraints

These come from the manual and are deliberate, not incidental:

- **Safe mode by default.** Every session starts de-identified. Items that
  capture names, dates of birth, or referrer details are locked until the user
  explicitly accepts the confidentiality risk.
- **The live preview shows five rows.** Older rows fall off the top, so a
  complete draft can't be screenshotted and filed as a record.
- **Nothing is persisted.** No localStorage, no backend, no network calls. State
  lives in memory and is destroyed on "Confirm & discard" or on page close.
- **No AI.** Composition is rule-based string assembly. No text is sent
  anywhere, which is the point — client data never leaves the device.
- **AU/UK English by default,** with a US toggle for spelling and date format.

## Architecture

```
src/
  content/
    checklist.json     generated from the manual (see below)
    psychometrics.ts   hand-authored instruments + score bands
  engine/
    compose.ts         option selections -> sentences
    overrides.ts       items whose prose can't be derived mechanically
    document.ts        sections -> full document
  components/          UI
```

`checklist.json` is generated by parsing the manual PDF. The parser lives in
`tools/` and is not needed at runtime — the committed JSON is the source of
truth for the app.

The engine works by deriving a template from the manual's own output sentences.
Given the option `self-harm` and the sentence *"Client reported no self-harm
ideation."*, it produces `"Client reported no {list} ideation."`, which lets
several selections fold into one grammatical sentence with an Oxford comma.

Items that restructure their sentence depending on the option chosen (currently
the MSE **Speech** item) are transcribed explicitly in `engine/overrides.ts`.

## Running it

Live: **https://smartaleex.github.io/noted-it/** — deployed from `main` by
`.github/workflows/deploy.yml`. It's a static build with no backend, so the
"nothing leaves the device" guarantee holds when hosted.

Locally:

```bash
npm install
npm run dev
```

## Status

Built from the manual's specification. Known gaps, in rough priority order:

1. **Sections 1–3 of the two letter documents are unnamed** ("Section 1",
   "Section 2") because the source document doesn't title them.
2. **Billing, subscriptions, and quota enforcement are UI-only.** The note
   counter increments locally; there is no account system, payment integration,
   or the manual's 200-notes-per-month ethical warning.
3. **No authentication.** The manual's login, trial, and organisational
   discount flows are not built.
4. **"Like"-able frequent selections** (manual: "not necessary for the first
   version") are not implemented.
5. **Grammar/spellcheck** relies on the browser's native spellcheck only.
